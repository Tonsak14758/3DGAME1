# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity **2023.1.22f1** 3D game (Built-in Render Pipeline, old Input Manager — `activeInputHandler: 0`). A physics-driven player sphere rolls around, aims with a crosshair, and picks items into an inventory. There is no build script, test suite, or CLI tooling: compiling and running happen in the Unity Editor. `Assembly-CSharp.csproj` / `3DGAME1.sln` are Unity-generated (don't edit by hand); there are no `.asmdef` files, so all scripts compile into `Assembly-CSharp` (except `Assets/Script/Editor/`, which Unity compiles into `Assembly-CSharp-Editor`; e.g. `ItemPickupEditor` shows a live `ItemProperties` preview in `ItemPickup`'s Inspector).

- Scenes: `Assets/Scenes/Testing.unity` (main gameplay sandbox) and `Assets/Scenes/MianMenu.unity` (sic). The Build Settings scene list is currently empty.
- `Assets/Script/` is the real game code; `Assets/Testing/` holds throwaway practice scripts (`CameraFollow`, `PlayerMover`) not part of the main gameplay; `Button_Up.cs` is an empty stub.

## Architecture

Scripts communicate mostly through **static state and static events** rather than Inspector references:

- `InventoryManager.IsOpen` (static bool) + `InventoryManager.Toggled` (static `Action<bool>`) — the inventory owns the cursor while open. `CameraController` stops reading mouse/keys when `IsOpen`; `HideWhileInventoryOpen` subscribes to `Toggled`. Opening/closing is driven by `KeyBindings.Inventory` (E).
- `KeyBindings` (`Assets/Script/Input/`) — one scene component; its `[SerializeField] KeyCode` fields are the *default* keys. Runtime keys live in a `KeyCode[]` indexed by the `KeyAction` enum, loaded from/saved to `PlayerPrefs` (`"Key_<Action>"`). API: static properties (`KeyBindings.Grab`, ...), `Get/Set(KeyAction)` (Set swaps duplicates), `ResetToDefaults()`, static `Changed` event. Auto-creates itself if missing. Gameplay scripts read keys only through it via legacy `Input.GetKey/GetKeyDown`. Adding a key = new `KeyAction` entry + default field + `DefaultKey` case + static property.
- `KeyBindMenu.IsOpen` (static bool) — in-game rebind menu (opened by `KeyBindings.KeyMenu`, K). Builds one row button per `KeyAction` from a prefab; click a row, press a key (Esc cancels). While open, `CameraController`, `InventoryManager`, `ItemGrabber` and `PlayerController` ignore input.
- `Crosshair.Target` (static GameObject) — raycast from screen center each frame while the cursor is locked (uses `DefaultRaycastLayers`, so the player sphere must be on the *Ignore Raycast* layer; triggers are hit). The crosshair hides itself whenever the cursor is unlocked.
- `PlayerInventory.Instance` (singleton) + `PlayerInventory.Changed` (static event) — `InventoryUI` redraws on `Changed`. Slots stack by `ItemId` **and** matching `ItemProperties` (`Slot.SameItemAs`).

Item properties (for future crafting stats): `MaterialData` is a ScriptableObject per resource (Create > Crafting > Material Data: weight per 1×1×1, hardness, toughness), referenced from `ItemPickup.material`. On collect, `ItemProperties.Read(go, material, fallbackName, edgeShape)` snapshots resource, hardness, toughness, edge (sharpest part's t/w/L, angle, sharpness, edge strength), shown color (property block `_Color`/`_BaseColor`, else material color), material color, shape (mesh name), size and weight (material × mesh-box volume, else Rigidbody mass, else volume). It's stored in `Slot.props`; `Key` is the stacking/icon-cache key (icons are cached per `ItemId + "|" + Key`).

Sharpness is never set by hand: all edge/combat formulas live in `SharpnessMath` (`Assets/Script/Crafting/`, tuning constants at the top) — edge angle Box `2·atan(t/w)` / Wedge `2·atan(t/2w)` (t,w = smallest/middle side), `S = H·(1−θ/90)`, edge strength `K·t/0.005`, chip chance `0.01·H/strength` (+5° per chip), cut `S·weight·speed`, blunt `weight·speed`, `IsEdgeHit`. Stats are read from the mesh (real thickness); `ItemPickup.Awake` grows Box Colliders to ≥ `MinColliderThickness` (0.01) only for physics. `slots` is fixed-size (padded to `maxSlots` in `Awake`); empty slots have `count <= 0` (`Slot.IsEmpty`). Minecraft-style clicking: `PlayerInventory.Held` is the stack on the cursor; `LeftClick(i)` (pick up / put down / merge / swap) and `RightClick(i)` (take half / place one) and `GatherSame(i)` (double left click: pulls all same-id stacks into slot i) and `PlaceOne(i)` (right-button spread: `InventorySlotClick` places one per slot entered while right is held) change it; `ReturnHeld()` puts it back (called from `InventoryUI.OnDisable` when the menu closes). `InventoryUI` adds an `InventorySlotClick` (`IPointerDownHandler`, needs an EventSystem) to every slot and draws the held stack under the mouse.
- `GameRules` (`Assets/Script/World/`) — Minecraft-style on/off rules, same pattern as `KeyBindings` (scene component, auto-creates, static properties, `Get/Set(GameRule)`, static `Changed`). Rules: `DoDaylightCycle` (default true, `DaylightCycle` on the sun only advances time while on) and `WorldInteraction` (default false). Adding a rule = `GameRule` entry + bool field + `Get`/`Set` cases + static property.
- `InteractionMachine` (`Assets/Script/Machine/`, own `areaRange` + `showArea` visual; independent of the `RadiusPreview` test tool; the area is centered on `Center` = middle of the machine's renderers, measured once in `Awake` as a rotation-relative offset from the pivot, not `transform.position`; the world-space circle is redrawn on `transform.hasChanged`) — the handless ball may only grab (F) / levitate (right click) **objects inside** a machine's area (the object's collider bounds touching the sphere; the player's position doesn't matter). Machines register in a static list in `OnEnable/OnDisable`. Gate with `InteractionMachine.CanInteractWith(collider)` (always true when `WorldInteraction` is on). `ItemGrabber.CanGrab` = that + `InRange`, used by `Crosshair` for its color; `ObjectLevitator` checks on pick and drops when the object leaves the area. `AutoCollector` is not gated.
- `ToolWielder` (on player) — when the active hotbar slot has an item (and `InteractionMachine.CanInteractAt(holdPoint)`), spawns a copy via `ItemTemplates.Spawn`, strips `ItemPickup`/`DroppedItem`, puts it on Ignore Raycast + Untagged, ignores collisions with the player, and drives its Rigidbody on a spring to a camera-relative hold point (handle = part farthest from the sharpest part; head up, thin axis → camera right). Mouse flicks = real-speed hits; `KeyBindings.Swing` (Mouse0) plays a click-swing animation whose damage uses a fixed weight-based speed. Hits (via `ToolHitReporter` on the tool) go through `SharpnessMath` (cut only if the sharpest part hits edge-first) to `HitTarget.TakeHit` (test target) and static `ToolWielder.Hit`. `ObjectLevitator` only works with an empty hand, so the two never overlap.
- `MenuState.AnyOpen` (`Assets/Script/UI/`) = Inventory / KeyBind / Build / Blueprint menu open; add new menus there. `ScreenMessage.Show(text)` shows a fading on-screen warning (falls back to `Debug.Log`).
- Building (`Assets/Script/Building/`, UI in `Assets/Script/UI/Building/`): `BuildingData` (ScriptableObject: name, description, optional icon, prefab) — the recipe is **read from the prefab**: every shape with a `BuildPart` (Item Id, optional `MaterialData`) is one required item, matched by **Item Id only**. `BuildMenu` (B) lists buildings → `BlueprintPlacer.Begin(data)` (on player): blueprint follows the crosshair; `PlaceBuilding` (Mouse0) place, `CancelBuilding` (Mouse1) cancel, wheel rotates (HotbarUI ignores the wheel while placing), `AutoPlace` (Mouse2) toggles sitting on the surface vs. a fixed distance. Red/invalid when outside every `InteractionMachine` area, overlapping (oriented box per renderer), or unsupported (no ground just below any piece, unless a part's material has `MaterialData.Floats`). `Blueprint.Create` instantiates the prefab under an inactive holder and `DestroyImmediate`s every MonoBehaviour (except `BuildPart`), Rigidbody and Joint so the copy never runs. Placed blueprint: unfilled pieces = hologram material + trigger colliders (aimable by the crosshair), added pieces = real materials + solid; all pieces added → `Instantiate(prefab)` + destroy blueprint. `BlueprintInteractor` (on player, `Interact` = Mouse1 on a placed blueprint, in reach and inside a machine area, else warning) → `BlueprintPanel` (rows = `BlueprintRow`; Add one / Add All / Remove — refunds the stored `Slot` copies, refused if `PlayerInventory.CanAddAll` fails). `PlayerInventory.Count/FindAny/TakeOne/CanAddAll` support this. `BlueprintPlacer.Busy` and `BlueprintPanel.ClosedThisFrame` stop the same click from also levitating / swinging / reopening.
- Cursor lock state (`Cursor.lockState`) is the shared "aiming vs. UI" mode flag: `CameraController` (Esc unlocks, click relocks), `InventoryManager`, and `Crosshair` all read/write it.

Pickup flow: `ItemGrabber` (on player, F key) → reads `Crosshair.Target` → `GetComponentInParent<ItemPickup>()` → range check to collider's closest point → `IconCapture.GetIcon(itemId, go)` → `PlayerInventory.Add(...)` → destroys the world object.

`IconCapture` is a static utility that renders a mesh-only copy of an object at `(0,-1000,0)` on **layer 31** with a hidden, lazily-created `DontDestroyOnLoad` camera, and caches the resulting Sprite per `ItemId`. Keep layer 31 unused elsewhere. It copies `MaterialPropertyBlock`s so colors from `ShapeColor` (which sets both `_BaseColor` and `_Color`) carry over.

`InventoryUI` builds its icon/count children at runtime under each child of `slotsParent`; the UI slot count should match `PlayerInventory.maxSlots`.

Templates & dropping: collected objects are destroyed, so `ItemGrabber`/`AutoCollector` first call `ItemTemplates.Store(key, go)` (key = `ItemTemplates.KeyFor(id, props)`, also the icon-cache key), which keeps one hidden copy per kind under an inactive `DontDestroyOnLoad` holder. `ItemDropper` (on player): while the inventory is open and `Held` isn't empty, a click not over UI (`EventSystem.IsPointerOverGameObject`) spawns copies via `ItemTemplates.Spawn` in front of the player — left = whole stack, right = one; each copy gets amount 1, a Rigidbody (mass = props.weight if added) and a `DroppedItem` pickup delay that `AutoCollector` respects (it also checks on Stay).

Bundles: dropping ≥ `ItemDropper.bundleThreshold` (5) at once spawns one `ItemBundle` prefab (box + Rigidbody + `ItemPickup` + tag chosen in the prefab: "PickUp" = F, "AutoPickUp" = touch) holding a copy of the stack (`Slot`: id, name, icon, count, props); mass = weight × count. `ItemGrabber.Grab` and `AutoCollector.TryCollect` check `ItemBundle` first and call `TryGiveTo(inv)` (whole stack with the saved props; refused + `ScreenMessage` when `inv.Add` fails). Same-item bundles merge on collision (lower instance id absorbs) and a new bundle merges into one within `mergeRadius`. The label (SpriteRenderer icon + 3D TMP "5x") billboards to the camera only while visible (`faceCamera` off = static label).

Touch pickup: `AutoCollector` (on player) collects objects tagged "AutoPickUp" (tag on the hit object or a parent) on trigger or collision enter, using `ItemPickup` data if present (else object name, amount 1). "PickUp" is the tag for F-grab items.

`Crosshair` highlights anything with an `ItemPickup` on it or a parent (same check as `ItemGrabber`), or tagged with its `targetTag` (default "PickUp").

## Conventions (follow when adding/editing scripts)

- Each script starts with a header block comment: `Date` (or `First Date` + `Date`), `Author: Tony`, `Use by:` (how to set it up in the Editor), `Purpose:`. Dates are `d/m/yyyy`.
- Sections marked `// ===== Fields =====`, `// ===== Unity messages (Unity calls these) =====`, `// ===== My methods =====`.
- Private `[SerializeField]` fields with `[Tooltip]`, `[Range]`, `[Header]`; beginner-friendly explanatory comments on most lines. Components are cached in `Awake`; `[RequireComponent]`/`[DisallowMultipleComponent]` used where appropriate.
- Static state is cleared in `OnDestroy` ("static values outlive the scene").
- Input reads are wrapped in small helper methods. Key/button reads use `Input.GetKeyDown(KeyBindings.X)` (never a hard-coded `KeyCode`); add new keys as fields in `KeyBindings`. Only the mouse-delta read in `CameraController` keeps an `#if ENABLE_INPUT_SYSTEM` branch.
